# 07. 시뮬레이션 계획 (2026-10-14)

LPDL v2(lpdlc-v2)로 효과를 **기술**할 수 있게 됐다. 이 문서는 그 기술을 **실행**해서 수치를 내는 단계의 계획이다.

## 1. 현재 위치

| 층 | 상태 |
|---|---|
| 효과 기술 (LPDL v2) | ✅ 문법, 검증, #202 기준 예시, 컴파일러 |
| 수치 코어 (`engine/`) | ✅ 합 정확 계산, 코인 분포, 피해 공식, 정신력 |
| LPDL → 엔진 연결 (`engine/runtime/`) | **M1에서 구현** |
| 턴 진행, 덱·손패, 적, 행동 정책 | M2 이후 |

## 2. 구성

1. **실행기** (`engine/runtime/`) — LPDL은 언어로만 두고 실행 의미는 엔진이 가진다
   - `on <event>` 블록 = 이벤트 핸들러. 같은 이벤트는 적힌 순서대로 실행 (R1)
   - `modify`는 즉시 적용하지 않고 **행동별 수정치**에 쌓음 → 피해 공식 각 위치가 자기 몫을 꺼내 씀
   - `limit` / `budget` / `every` / `next_turn` / `defer` 상태를 실행기가 관리
   - `hook 이름` → Python 함수 레지스트리
2. **표준 키워드** — `keywords/standard.lpdl`로 LPDL에서 정의 (엔진은 원시 동작만). M1은 진동·진동 폭발만 내장
3. **상태 모델** — 유닛(체력, 흐트러짐 선, 정신력, 속도, 보호막, 상태 {이름: (위력, 횟수)}, 수치형 {이름: 값}, 편성 순서), 전투(턴, 아군·적, 보유·공명 자원)
4. **턴 진행** (M2) — 턴 시작 → 속도 → 스킬 선택·대상 → 전투 시작 → 속도순 행동 → 턴 종료
5. **계산 모드** — 정확 열거(코인 앞/뒤 모든 경우, 일방 공격 1회) / 몬테카를로(여러 턴, 시드 고정)
6. **정책** (M4) — 고정 순환 → 탐욕 → 롤아웃/MCTS. 탐색이 탐욕과 다른 지점 = 운용 노하우

## 3. 단계

| 단계 | 목표 | 검증 |
|---|---|---|
| **M1** | 실행기 + **일방 공격 1회** 정확 열거 ("상태 X에서 #202 S1을 허수아비에게 → 피해 분포·자원 변화") | 원문 문장별 시나리오 테스트 + 손계산 |
| M2 | 인격 1명 × 여러 턴, 고정 순환 | #202 자원 흐름이 `02` 손계산 추정과 맞는지 |
| M3 | 팀 5~6명, 아군 상호작용, 합을 하는 단순 적 | 팀 구성 민감도 |
| M4 | 정책 탐색 → 규칙 추출 → 운용 가이드, 팀 최적화 | 커뮤니티 공략 대조 |

병행 가능: AST 정적 분석(P3) — 자원별 gain/consume 집계로 "턴당 생산 vs 소비", "임계치 도달 최소 턴".

## 4. M1 실행 의미 (가정 — 확인 필요 항목 표시)

| 항목 | M1 처리 | 상태 |
|---|---|---|
| 일방 공격 | 모든 코인 적중. 코인 k 위력 = 기본 + Σ(1..k 중 앞면 코인 위력) + 최종 위력 수정 | 규칙 3장 |
| `apply K potency P [count C]` | 없으면 위력 P·횟수 C(기본 1) 생성, 있으면 위력 +P·횟수 +C(기본 0) | [확인 필요] |
| `gain X.count N` (상태 없음) | status 계열은 무시, charge 계열(보존·충전)은 생성 | [확인 필요] |
| 횟수 0 | status 계열은 제거, charge 계열은 위력 유지 | [확인 필요] |
| `count_max` | 초과분은 버림. `ev.amount`는 초과 포함 요청량 | 코트 원문 |
| `consume N` / `up_to N` / `all` | 부족하면 0 / 있는 만큼 / 전부 | LPDL 정의 |
| `burst K` | 대상 K 위력만큼 흐트러짐 피해 × (1 + 흐트러짐 피해 증가 합). 횟수는 줄이지 않음 (원문이 감소를 따로 적음) | 키워드 사전 |
| 흐트러짐 피해 | M1은 누적 지표로만 기록 (게이지 규칙 미정) | [확인 필요] 규칙 4장 |
| `convert A -> B` | B = A의 수치, A = 0 | [확인 필요] |
| `deal 대상 pierce X` | X × 대상 관통 내성 배율 체력 피해 | [확인 필요] |
| 기본 스킬 / 기본 공격 스킬 | `basic_skill` = S1~S3(+variant)·DEF, `basic_attack` = S1~S3(+variant) | [확인 필요] |
| 패시브 조건 | 전투의 보유 자원 / 공명 수로 판정. 분석용 `force_passives` 옵션 | 규칙 1장 |
| 수비 스킬, 합, 치명타, E.G.O | M1 범위 밖 | |

## 5. 사용자에게 받을 것

1. 턴 구조 규칙: 손패 장수, 슬롯별 스킬 선택, 덱 재구성 시점 (M2 전 필요)
2. 위 표의 [확인 필요] 항목
3. M1 골든 테스트용 손계산 예제 1~2개 (예: #202 S1, 보존 위력 3, 대상 진동 6)
4. 적 시나리오 범위: 허수아비 / 고정 위력 보스 / 거울 던전 대표 적

## 6. M1 구현 현황 (2026-10-14)

`engine/runtime/` — `state.py`(유닛·전투 상태), `interp.py`(LPDL 실행기), `loader.py`(DB 스탯 + spec), `action.py`(일방 공격 1회, 턴 시작/종료, 정확 열거)

```python
from engine.runtime import *
rt = load_runtime()                                   # ../lpdlc-v2/examples 의 spec 로드 + 검증
b = Battle([load_unit(202, name="료슈"), dummy()])
outs = simulate_action(rt, b, "료슈", ("S1", 0), "허수아비")   # 코인 앞/뒤 모든 경우
expect(outs, lambda o: o.result.damage)               # 12.0
```

테스트 `tests/engine/test_runtime_202.py` (11개): 기본 피해 손계산, 보존·코트 연동(R2), 코트 50 피해량, 아르뮈르 소모·전환(R4),
턴당 2회 제한, S3 코인3 진동 폭발 3회(R1) + 되먹임 패시브, 패시브 조건, 누적 소모 10당 보존 위력, 턴 종료 보호막, 원 킥 교체.

M1에서 추가로 정한 실행 의미:
- `gained` 는 **적용 전**에 발생 (획득 전 상태로 조건 판정, `modify amount` 반영), `consumed` 는 **적용 후** 발생
- 수치형 키워드는 0 이어도 보유 상태 유지 (코트 0). 제거는 `convert` 로만
- 핸들러 순서: 행동 중인 스킬 블록 → 현재 코인 블록 → 편성 순 유닛별 패시브 → 보유 키워드 정의
- 표준 상태 턴 종료 감소는 M1 임시 내장 (진동·충전 -1) → `keywords/standard.lpdl` 로 옮길 예정

미구현: 합, 수비 스킬, 치명타, E.G.O, hook 함수 (#202 hook 2개는 기록만), 아군 이벤트
