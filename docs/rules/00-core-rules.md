# 공통 규칙 (사용자 제공, 2026-10-13)

엔진(P2)의 정답 기준. 여기 적힌 내용은 `tests/engine/` 골든 테스트로 옮긴다.
**[확인 필요]** 표시는 아직 정의가 확정되지 않은 부분. 엔진에서는 해당 값을 파라미터로 빼 두었다 (`engine/params.py`).

## 0. 죄악 속성 순서
`분노, 색욕, 나태, 탐식, 우울, 오만, 질투` — E.G.O `cost`, E.G.O `resistance` 배열이 이 순서.
인격 `resistance` 배열은 `참격, 관통, 타격` 순서.

## 1. 패시브 발동 조건

### 1.1 보유 (`activeCond = "보유"`)
- E.G.O 자원: 스킬을 사용할 때마다 그 스킬의 죄악 속성 자원이 1 쌓인다. (팀 공용 풀)
- 해당 속성 자원이 **N개 이상**이면 패시브 발동.
- 예) 전 턴에 분노 스킬 4개 사용 → 분노 자원 4 → **이번 턴부터** `[분노 보유 4]` 발동.
- 복수 속성 조건(`분노, 오만 x2`)은 **각 속성이 각각 N 이상**.
- 동기화 3의 방어/회피 스킬은 속성이 없어 자원을 만들지 않는다 (데이터 기준, `docs/04-data-notes.md`).
- [확인 필요] E.G.O 사용으로 자원이 N 미만이 되면 같은 턴 안에서도 즉시 꺼지는지.

### 1.2 공명 (`activeCond = "공명"`)
- **이번 턴에 팀 전체가** 사용하는 스킬 중 해당 속성 스킬 수가 **N 이상**이면 그 턴에 발동.
- 예) 이번 턴에 오만 스킬 3개가 잡힘 → `[오만 공명 2]`, `[오만 공명 3]` 모두 발동.
- 복수 속성 조건은 보유와 같게 **각각 N 이상**으로 처리.
- [확인 필요] "최대 공명 수"(예: #204 "최대 공명 수 1당 …")와 "절대 공명"의 정의 — 슬롯 배치 순서상 연속된 동일 속성 수인지.

## 2. 코인 판정
- 앞면 확률 = **50% + 정신력 × 1%** (정신력 음수면 감소).
- 엔진에서는 [0, 1]로 클램프. (정신력 범위가 ±45라 실제로는 5%~95%)
- 스킬 위력 = 기본 위력 + Σ(앞면인 코인의 코인 위력). 코인 위력이 음수인 스킬도 있음 (예: #45 S4 `15 + (-5)`).

### 2.1 정신력 변화
- 기본: **합 승리 시 정신력 +10, 2합부터 1합당 20%씩 증가** → `10 × (1 + 0.2 × (합 횟수 − 1))`
  - 1합 10, 2합 12, 3합 14
  - (처음 예시 "3합 후 16"은 정정 전 기준. 14가 맞음 — 확정)
- 인격마다 특수 정신력 조건이 있음 → 인격 spec에서 덮어씀.
- [확인 필요] 합 패배 측 정신력 변화, "합 횟수"에 동점 비교도 포함되는지.

## 3. 합 (Clash)
1. 합을 하는 두 캐릭터가 **남아 있는 코인 전부**를 토스해서 위력을 비교.
2. 위력이 낮은 쪽의 **첫 번째(남은 것 중 가장 앞) 코인이 파괴**됨.
3. 위력이 같으면 **양쪽 다 코인 보존 후 다시 합**. 이것도 행동을 실행한 것으로 취급되어 행동 효과(출혈 등)의 영향을 받음.
4. 한쪽 코인이 모두 파괴될 때까지 반복. 남은 쪽이 합 승리 → **남은 코인으로 공격**.
5. 합 횟수(동점 포함 비교 횟수)는 피해량 공식의 `합 횟수 × 0.01`에 들어감.

예시 (사용자 제공):
```
내 스킬: 코인1 [적중시] 파열 1 / 코인2 [적중시] 파열 횟수 1 / 코인3 [적중시] 파열 3
상대: 효과 없는 2코인 스킬

토스 → 승리 (상대 코인1 파괴)
토스 → 패배 (내 코인1 파괴 = "파열 1 부여" 코인 제거)
토스 → 승리 (상대 코인2 파괴)
→ 합 승리, 내 코인 2·3으로 적 타격
```
- 합 승리 후 공격 단계에서 코인을 다시 토스하고, 코인 k의 피해 = "기본 위력 + 남은 코인 중 k번째까지 앞면 코인 위력 합". (확정)

### 3.1 행동 순서
- 속도가 빠른 순서대로 진행. 같으면 내부 메커니즘이 있으나 알 수 없음 → **엔진은 입력 순서(안정 정렬)로 처리**.

### 3.2 합 가로채기 / 일방 공격
- 합은 **나를 가장 마지막에 타게팅한 대상**과 진행. 단, 내 속도가 그 대상보다 **같거나 높은 경우**에 한함.
- 일방 공격: 대상과 합을 하지 않고 때리는 것.
- 방어 / 반격 / 합 가능 방어 / 합 가능 반격은 **자신에게 처음 들어오는 공격**에 반응.
  - 예) 수비 스킬 슬롯이 속도 4 적과 합을 잡았어도, 속도 7 적이 먼저 일방 공격하면 반격 등은 속도 7 적에게 나감.

## 4. 흐트러짐
- 체력의 일정 비율마다 흐트러짐 선 존재 (현재 최소 1개, 최대 3개). **인격마다 다름.**
  - 데이터: wiki.gg에서 보충 → DB `identity_ext.stagger_json` (최대 체력 %, 예: #13 `[65, 35]`, #204 `[40]`). 189개 전부 확보.
- 체력이 흐트러짐 선 이하가 되면 흐트러짐 발생. 단, **직접 피해만** 해당 (출혈 피해 등은 에고 기프트 없이는 불가).
- 흐트러짐 상태: **물리(참·관·타) 내성만** 아래 배율로 바뀜 (죄악 내성은 그대로). 한 번에 여러 선이 깨지면 흐트러짐+, 흐트러짐++.

| 상태 | 물리 내성 배율 |
|---|---|
| 흐트러짐 | ×2 |
| 흐트러짐+ | ×2.5 |
| 흐트러짐++ | ×3 |

- 엔진: 원래 물리 내성 등급을 **대체**하는 것으로 구현 (`Params.stagger_phys_mult`, `HitContext.stagger`).
- 흐트러지면 이번 턴 예정된 행동 전부 취소, 다음 턴까지 행동 불가.
- [확인 필요] 회피의 "흐트러짐 게이지 회복"과 흐트러짐 선의 관계 (게이지 = 선까지 남은 체력 버퍼인지).

## 5. 수비 스킬
- 캐릭터 칸을 클릭해서 생성. 스킬 슬롯 2개 중 **아래 스킬 대신** 생성됨.
- 사용되면 다음 스킬이 평소대로 내려오고, 사용되지 않으면 다음 턴에도 맨 아래 칸에 그대로 남음.

| 종류 | 데이터 `atk_type` | 효과 |
|---|---|---|
| 방어 | 방어 | 위력만큼 보호막. 디버프는 막지 못함 |
| 회피 | 회피 | 회피 위력 ≥ 적 스킬 위력이면 피해 무효, 공격이 없었던 것으로 취급. 위력만큼 흐트러짐 게이지 회복 |
| 반격 | 반격 | 적 피해를 받은 뒤 일방 공격 |
| 합 가능 방어 | 가드 (추정) | 합 승리(적 코인 전부 파괴) 시 위력만큼 흐트러짐 피해 |
| 합 가능 반격 | 반격 + `[합 가능 반격]` 태그 | 일반 공격 스킬을 언제든 만드는 것과 거의 같음 |

- [확인 필요] 회피가 코인 단위로 판정되는지(적 코인마다 비교) 스킬 단위인지.

## 6. 피해량 공식

### 내성 등급 (확정)
| 등급 | 영문 | 배율 | 가산값 |
|---|---|---|---|
| 취약 | Fatal | ×2 | +1.0 |
| 보통 | Normal | ×1 | 0 |
| 견딤 | Endure | ×0.75 | −0.25 |
| 내성 | Ineff | ×0.5 | −0.5 |

견딤은 현재까지 죄악 내성에서만 등장.

```
피해량 = ( 스킬 결과값 + Σ고정 피해 증감₁ )
       × ( 1
           + 참·관·타 내성 증감
           + 죄악 내성 증감
           − 공방 수식 결과값
           + (치명타 시 0.2)
           + 죄악 공명 피해 증가값
           + 합 횟수 × 0.01 )
       × ( Σ 피해량 증감 [스킬·코인·패시브·버프·디버프, 합연산] )
       + Σ고정 피해 증감₂
```

| 항목 | 정의 | 상태 |
|---|---|---|
| 스킬 결과값 | 해당 코인 적중 시점의 최종 위력 | 3장 [확인 필요] 참고 |
| 고정 피해 증감₁ / ₂ | 배율 적용 전 / 후에 더해지는 고정값 | [확인 필요] 대표 효과 예시 |
| 참·관·타 내성 증감 | 내성 등급별 가산값 (= 배율 − 1). 흐트러짐 중엔 4장 배율로 대체 | 확정 |
| 죄악 내성 증감 | 같은 등급표 | 확정 |
| 공방 수식 결과값 | 공격 레벨과 방어 레벨 차이로 계산 | [확인 필요] 정확한 식 (현재 `(방어−공격)/(|차이|+25)` 가정) |
| 치명타 | +0.2 | 확정 |
| 죄악 공명 피해 증가값 | 공명 수에 따른 가산 | 대부분 **인격 패시브 / 서포트 패시브** 효과로 들어옴 → 공통 규칙 기본값 0, spec에서 처리 |
| 합 횟수 × 0.01 | 이 공격 전 합 비교 횟수 | 확정 |
| 피해량 증감 (셋째 괄호) | 모든 "피해량 +X%" 계열 합연산 | 엔진은 `1 + Σ`로 가정 [확인 필요] |

## 7. 서포트 패시브
- 출전하지 않고 **편성(벤치)에 있기만 해도** 발동 가능.
- 조건(보유/공명)은 메인 패시브와 같은 방식으로 판정.

## 8. 아직 받지 않은 규칙
- 표준 키워드(출혈/파열/진동/침잠/화상/호흡/충전)의 처리 순서 — 키워드 사전 정의를 기준으로 하되 예외 확인
- E.G.O: 자원 소모, 정신력 소모, 침식 조건

## 9. 효과 텍스트 해석 규칙 (확정, 2026-10-14)

LPDL v2(lpdlc-v2 `docs/design.md` §4)와 같은 규칙. 엔진은 spec이 이 규칙대로 작성됐다고 가정한다.

- **R1** 줄이 다른 같은 태그(`[적중시]` 등)는 독립된 효과이며, 적힌 순서대로 모두 발동한다. 한 태그 문단 안의 `-` 하위 항목은 하나의 효과.
  예) #202 S3 코인 3: `[적중시] 진동 폭발` + `[적중시] 보존 위력 3 이상이면 진동 폭발 2회` → 조건 충족 시 총 3회.
- **R2** "자신의 ~ 효과로"는 자기 자신이 원인인 효과만(스킬·패시브 모두). 아군 지원 효과로 받은 것은 제외. 출처 제한이 없으면 "~ 획득 시"처럼 쓰인다.
- **R3** 텍스트의 출처 나열("스킬, 패시브")을 문자 그대로 좁히지 말고 주어("자신의")를 기준으로 판단한다 (프로젝트 문 텍스트는 표현이 일정하지 않음).
- **R4** 0이 되면 다른 키워드로 바뀌는 수치형 키워드(예: 아르뮈르 에비이예 → 르누아르 개버딘 원단 코트)는 0인 상태로 존재하지 않는다. "X가 있으면" = 1 이상 보유.
- **R5** 스킬 효과의 "해당 효과가 ~로 변경됨"은 그 인격의 키워드 상태 전환 (#202 DEF: 코트 ↔ 아르뮈르).
